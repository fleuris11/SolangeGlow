# Routes de l'application web

Inventaire de chaque `page.tsx` de `web/src/app/[locale]/`. Toutes les adresses commencent par la langue (`/fr`, `/en` ou `/sk`) ; le tableau l'omet. Document généré par lecture du code : ce qui n'a pas pu être établi est marqué « ? ».

## Résumé

- Pages au total : **93**
- Par groupe : app = 67, focus = 21, chat = 3, embed = 1, autres = 1.
- Pages avec données fictives (`src/lib/demo`) : **68**, voir ci-dessous.
- Pages sans état de chargement détecté : **15** (`/[slug]/rdv`, `/[slug]/shop/[product]`, `/[slug]/shop`, `/academie/[slug]`, `/academie`, `/aide`, `/certificat/[code]`, `/create`, `/pages/[slug]`, `/selection/[slug]`, `/selection`, `/embed/[slug]`, `/auth`, `/hors-ligne`, `/invite/[code]`).
- Pages sans état vide détecté : **36** (beaucoup n'ont pas de liste, donc rien à vider).
- Pages sans état d'erreur détecté : **32**, dont 18 avec un `catch` seulement (l'erreur est avalée ou gérée sans écran dédié).
- Aucun fichier `loading.tsx`, `error.tsx` ni `not-found.tsx` n'existe dans `src/app` : les états de chargement et d'erreur sont gérés dans les composants (Skeleton, `isPending`, `notFound()` des pages serveur).

### Comment lire le tableau

- **Rendu** : toutes les pages sont des composants serveur (aucun `page.tsx` n'est « use client »). « Serveur » = les données sont lues côté serveur Next (`lib/api/server.ts`, avec cache, SEO). « Coquille serveur + écran client » = la page ne contient presque rien et l'écran charge ses données dans le navigateur (React Query, `lib/api/*.ts`).
- **Endpoints** : chemins relatifs à `/api/v1` ; le navigateur appelle `/api/*` et Next relaie vers Django. Liste établie automatiquement en suivant les composants rendus puis les fonctions de `lib/api/*.ts` qu'ils utilisent (une fonction importée mais non utilisée est ignorée). Partout, `GET /me` (via `useMe`) peut s'ajouter pour connaître la personne connectée. Pour les écrans qui regroupent beaucoup d'actions, la liste peut être un peu plus large que ce que la page montre au premier affichage.
- **États** : détection par motifs dans le code suivi (Skeleton, `isPending`/`isFetching` pour le chargement ; `EmptyState` ou test de liste vide pour le vide ; `isError`, `role="alert"`, `setError`, `notFound` pour l'erreur ; `toast` ou écran de fin pour le succès). « non repéré » veut dire que rien n'a été trouvé, pas que c'est prouvé absent ; à confirmer à l'écran.
- **Connexion requise** : « SignedIn » = l'écran est enveloppé dans `SignedIn` (lit le cookie `sg_signed_in` ; sinon affiche un bouton « Se connecter »). « l'API refuse sinon » = pas de garde visible, la réponse 401 de l'API fait foi.
